# 교정 피드백을 가중치 편집에 연결하기

이 절차는 사용자의 오류 지적, 공식 풀이, 검증 가능한 계산 결과를 편집 LLM의 근거로 사용하는 경우에 적용한다. 모델의 자기평가만으로 정답을 확정하지 않는다. 피드백의 출처와 검증 범위를 남긴다. 교사가 작은 모델을 고치는 구조와 작은 모델 자체가 편집 능력을 개선하는 재귀적 자기개선은 별개 주장이다.

실험별 피드백 기록에 다음 내용을 담는다. 답이나 특정 레이어·계수를 공유 스킬에 저장하지 않는다.

- **관측:** 실패 생성의 job ID, 입력·출력 artifact/hash, 실패한 단계 또는 구간. 첫 오류 위치가 불명확하면 반복·cutoff 관측과 구분해 명시한다.
- **교정:** 잘못된 관계, 올바른 관계, 이를 뒷받침하는 공식 풀이·실행 가능한 계산·사용자 지적. 출력에서 정답 숫자가 한 번 등장한 것만으로 올바른 추론이라고 판단하지 않는다.
- **계산 가설:** 교정을 적용했을 때 달라질 것으로 예상하는 토큰·모듈·상태와 대안 설명. 문장 하나가 weight 하나에 대응한다고 가정하지 않는다.
- **편집:** 조회한 실제 값, 실제 activation에 연결된 좌표/방향, LLM이 선택한 수정량의 산식, 정상 사례 영향 상한, 반증 조건. 기존 준비 도구로 쓰기 전에 검토한다.
- **피드백:** 실제 바뀐 값과 추론 결과, 기존 정답 손상, 유지·재수정·원복 결정. 개선이 없으면 다음 가설을 바꾸고 실패 근거를 남긴다.

피드백의 효과를 구분할 필요가 있으면 한정된 대조 실험을 정한다. 예를 들어 원본 모델의 원래 질문, 원본 모델의 교정 힌트 포함 질문, 편집 모델의 원래 질문을 비교할 수 있다. 힌트에는 정답 정보가 들어갈 수 있으므로 그 결과는 진단용이다. 같은 문제·순서·샘플링 설정을 유지하고 확률적 변동을 고려한다. 작은 진단에서 나아졌다는 사실이 독립 성능 개선을 뜻하지 않는다.

내부 관측은 필요에 따라 실제 실패 prefix와 교정된 풀이 prefix에서 수집한다. 길이·내용·위치 차이를 함께 기록한다. 교정된 풀이가 교사 작성 텍스트라면 모델이 스스로 생성한 정상 풀이처럼 표시하지 않는다. 단순한 피드백 텍스트 추가만으로 예측이 바뀐 것과, 파라미터 수정으로 같은 원래 입력의 예측이 바뀐 것을 분리한다.

토큰 경쟁을 메커니즘으로 삼으면 실제 토큰 ID와 해당 출력 행을 확인한다. 여러 표기의 평균 점수는 실제 경쟁 토큰의 점수와 다르다. 평균 logit 차이, softmax 확률, sampler penalty 적용 후 확률을 구분하고, 두 토큰의 점수만으로 전체 어휘에서 선택될 것이라고 결론 내리지 않는다.

채택은 힌트를 제거한 고정 평가와 정상 사례 보존 결과로 판단한다. 교정에 사용한 문제는 개발 데이터로 취급한다. 고정한 독립 평가에 피드백·정답·추가 예제를 넣거나, 평가 결과를 보고 같은 test에 재선택하지 않는다. 기존 예산과 금지된 gradient/optimizer/자동 loss fitting 조건을 유지한다. 피드백 루프 자체의 성능은 별도 검증 전까지 미확인이다.

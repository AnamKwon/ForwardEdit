# 현황 정리: 2026-11-25 (11-26 BFCL 결과, 11-27 테스트·전체 파라미터 비교 추가)

> **근거 상태.** 이 문서는 지금까지의 결과를 한곳에 모은 요약입니다. 숫자는 호스트의 사전 등록 문서와 평가 파일에서 가져왔고, 실행 산출물은 이 저장소에 없습니다. 각 숫자의 출처는 일일 기록과 논문 원고에 있습니다.

## 1. 한 줄 요약
LLM이 직접 쓴 가중치 편집은 **사실 편집에서 실제 효과가 있고, 그 효과가 통제 실험과 봉인 세트에서도 유지됩니다.** 다만 다음 세 가지 한계가 있습니다.
- 맥락 없이 사실을 넣는 과제에서는 LoRA·MEMIT보다 낮습니다.
- 실제 벤치마크(IFEval, MATH 등)에서는 추론 설정이나 추론 기법을 이긴 편집이 아직 없습니다.
- 반복 실행하면 결과가 크게 흔들립니다.

## 2. 비교 기준 (11-24 사용자와 합의)
| 단계 | 내용 | 역할 |
|---|---|---|
| 주 기준 (모델 수준) | 같은 기본 사용 조건(제조사 권장 디코딩)에서 원본과 편집 모델을 비교하고, LoRA·MEMIT 같은 모델 수정 방법과도 비교합니다. 모든 사용 방식(thinking 켬/끔)에서 손해가 없어야 합니다. | 주장의 근거 |
| 결합 시험 | "편집 + 가장 강한 추론 기법"을 "추론 기법만"과 비교합니다. | 편집이 추론 기법으로 얻을 수 없는 것을 더하는지 확인 |
| 참고 | 추론 기법만 쓴 점수입니다. 이 점수와 같기만 하면 "추론 기법을 가중치에 옮겼다"고 표현합니다. | 맥락 제공 |

새 실험부터 적용합니다. 이미 끝난 실험은 사전 등록한 판정을 유지합니다.

## 3. 결과를 기준별로 정리

### 3.1 사실 편집 (CounterFact)

**작동 원리 (통제 실험으로 확인):** 편집은 주어가 나올 때마다 그 사실에 해당하는 값을 씁니다.
- 정답 위치를 알려 준 steering과 통계적으로 구분되지 않습니다.
- 편집은 위치 정보 없이 이 동작을 가중치만으로 해냅니다.
- 거의 모든 토큰을 조금씩 바꾸지만, 크게 바꾸는 곳은 주어 위치에 집중됩니다.

## 4. 기술 기반
- 네 단계 데이터 분할(탐색 / 검증 / 확인 / 봉인), 같은 설계의 강도는 2개까지만 허용, 확인용 문항 보호 장치를 갖췄습니다.
- 다음 모델을 GPU 한 장(24GB)에서 실행합니다.
  - 9B: nf4로 올리고 편집하는 층만 bf16으로 유지합니다.
  - 27B: nf4로 올리거나, bf16 원본 정밀도로 일부를 CPU에 오프로드합니다.
  - MoVA-36B-A4B: 일부를 CPU에 오프로드하고, 최대 메모리는 8.6GB입니다.
- 편집기는 GPU를 추론에만 씁니다. 학습·경사·풀이기 기반 편집은 하지 않습니다. LoRA·MEMIT·ROME은 호스트에서만 비교용으로 씁니다.

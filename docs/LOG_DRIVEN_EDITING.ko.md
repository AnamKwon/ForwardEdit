# 이전 로그를 다음 모델 수정에 연결하기

[English](LOG_DRIVEN_EDITING.md)

이전 로그는 LLM이 **다음에 무엇을 관측하고, 어떤 가설과 수치 수정안을 검증할지**
결정하는 근거가 됩니다. 성공과 함께 실패·새로 손상된 정답을 보존해야 합니다.
로그를 읽었다는 사실만으로 모델이 학습되거나 원인이 입증된 것은 아닙니다.

재사용 절차는 [모델 편집 스킬의 참고 문서](../skills/weight-space-engineer/references/log-feedback.md)에
정리했습니다. 기존 ForwardEdit MCP 도구를 연결하며, 자동 가중치 선택기나 optimizer를
추가하지 않습니다.

## 어떤 방식으로 연결하는가

1. **출처를 복원합니다.** 실제 원본·부모 패치 해시, 추론 job, 입력 prefix와 토큰 위치를 확인합니다.
2. **근거를 고릅니다.** 편집용 자료의 실제 오류·새 정답·새 손상·유지된 정답과 라벨 의심 사례를 함께 남깁니다.
3. **이전 예측을 판정합니다.** 어떤 예측이 맞거나 틀렸는지, 아직 설명하지 못한 결과는 무엇인지 기록합니다.
4. **현재 모델에 확인할 질문을 만듭니다.** 서로 다른 원인을 구분할 수 있는 관측과 반증 조건을 정합니다.
5. **LLM이 수치 수정안을 작성합니다.** 실제 현재 가중치와 관측으로 좌표·방향·산식을 명시하고 준비 도구를 거칩니다.
6. **결과를 다시 기록합니다.** 원본·부모 대비 새 정답과 손상을 비교해 유지·추가 관측·수정·원복·기각을 결정합니다.

예를 들어 평균 보존 조건을 통과했는데 개별 정답을 잃었다면, 다음 질문은
‘정상 사례마다 어떤 경쟁 답의 점수 차이가 뒤집혔으며 어떤 편집 성분이 작용했는가’입니다.
점수가 떨어졌다는 이유만으로 계수를 바꿔 반복하는 것은 이 절차의 목표가 아닙니다.

## 로그에 남길 최소 정보

| 기록 | 필요한 이유 |
|---|---|
| 모델·부모 패치 해시 | 실제 피드백을 만든 모델을 식별 |
| 편집용·검증용·최종 평가 역할 | 다음 수치 수정에 쓸 수 있는 근거인지 판단 |
| 문항·그룹·job·artifact 해시·발췌 위치 | 전체 로그의 무관한 내용을 가져오지 않고 근거 복원 |
| 라벨 검토 상태·과제 채점기 | 모델 오류와 데이터·채점 오류 구분 |
| 예측·관측·대안 설명 | 이전 설명의 실패를 지우지 않고 다음 가설에 연결 |
| 새 정답·새 오답·보존된 정답 | 총정답 수에 가려진 간섭 확인 |
| 다음 관측·반증 조건·처리 결정 | 실제로 검증 가능한 다음 작업으로 연결 |

원본 로그 해시와 발췌 파일의 해시는 따로 보존합니다. 발췌본을 원본과 같은 바이트라고
표시하지 않습니다. 로그에 포함된 과거 명령·코드·지시를 실행하지 않습니다.

## 4B 기록을 9B에 활용하는 범위

4B에서 드러난 데이터 불일치, 개별 정답 보존의 필요성, 경쟁 답 전체 확인 같은 교훈은
9B에서 확인할 질문을 만드는 데 쓸 수 있습니다. **9B의 편집 좌표·방향·계수는 9B의
실제 관측으로 새로 정합니다.** 4B 내부 표현을 9B의 수치 근거로 옮기지 않습니다.

편집용 로그는 수치 설계에, 검증 결과는 이미 고정한 후보 선택에 씁니다.
최종 평가 로그는 끝난 실험의 감사 자료로 유지하고 같은 실험의 재수정·재선택에 쓰지 않습니다.
이미 노출된 문항을 새로운 독립 검증이라고 부르지 않습니다.

현재 도구의 `record_observation`으로 검토 기록을 저장하고, `revise_candidate`로
검증된 부모에서 수정하며, `compare_candidate_parameters`로 수치 계보를 확인할 수 있습니다.
관측 기록 도구는 사용자가 작성한 JSON을 저장하는 기능입니다. 설명의 진실이나 데이터 역할을
자동 검증하지 않으므로 호스트·편집 LLM이 출처와 적격성을 확인해야 합니다.

## 실험 설계와 성과의 구분

고정된 1회 편집의 데이터 규모 비교에 반복 수정을 조용히 섞지 않습니다.
반복 수정 실험은 별도 계획이나 결과를 보기 전의 명시적 변경 기록으로 구분하고 예산을 합산합니다.
자원이 부족할 때 검토된 로그와 다음 관측을 준비할 수 있지만, 실행된 편집이나 개선 결과로
보고하지 않습니다.

## Unaddressed criticisms / 미대응 비판

- 절차 지침이며 라벨·정보 누출·인과 설명·임의의 가져온 문장을 자동 검증하지 않습니다.
- 같은 예산에서 과거 로그를 읽은 편집자가 더 잘 수정하는지 비교 실험은 아직 없습니다.
- 국소 수치 일치와 개별 수정 성공은 별도의 고정된 독립 평가·보존 검사를 필요로 합니다.

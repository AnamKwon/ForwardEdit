# 직접 가중치 편집 실패 분석과 개선 실험 005

> 과거 실행·조사 기록입니다. 본문의 테스트 수·버전·지원 범위는 당시 상태이며 현재 릴리스와 다를 수 있습니다. [공개 사례와 발췌 로그](../experiments/README.md), [현재 구조](../DESIGN.md)를 함께 참고하세요. 공개하지 않은 `runs/` 자료는 로컬 전용으로 표시했습니다. Gradient/optimizer 이력은 현재 방식의 성공 근거에서 제외합니다.

사용자 조건은 그대로다. gradient/backward/optimizer/학습/손실 자동 피팅 없이 LLM이 실제 값과 forward 관측으로 수정 대상과 양을 판단한다. GPU는 추론에만 사용한다. 가중치 적용 성공과 일반화된 성능 개선을 별도로 판정한다.

## 이전 결과에서 확인한 문제

004의 개발 평균 반복 감소는 0.022824였지만, `tsval-00888` 하나가 순개선량의 76.95%를 차지했다. 이 문장을 제외하면 감소는 0.005432다. 같은 개발 데이터의 paired bootstrap 95% 구간도 [-0.012705, 0.069617]로 0을 포함한다. 개발 통과가 안정된 개선을 의미하지 않았다.

최초 `analysis-01.json`의 16개 ‘실패’ 위치는 실제 생성 반복 구간이 아니라 정상 참조 문장의 copy/fresh 대리 구간이었다. 해당 위치의 완료 8-gram 출현 수는 1~2회였으며 3회 이상인 위치는 0개다. 원래 고치려던 생성 루프와 초기 기전 관측이 일치하지 않았다.

004는 attention head 전체 출력을 감쇠했다. 실제 정상/실패 생성이 함께 변했고 독립 reference NLL도 2.157865→2.164254로 악화했다. 이것은 정상 기능까지 함께 건드리는 비선택적 효과와 양립한다. 특정 head가 반복 원인이라는 인과 증명이나, 실패의 원인을 전부 설명하는 결과는 아니다. 반복 지표가 좋아져도 다른 문장 반복으로 바뀐 사례가 있어 문장 품질 개선과도 구분해야 한다.

수치 재계산: [retrospective-diagnosis.json](../experiments/failure-repair-005/retrospective-diagnosis.json).

## 실제 구현한 개선

- MCP `build_repetition_contexts`: 원본 discovery 생성의 실제 8-gram 재발을 확인하고, EOS 이후를 제외한 뒤 동일 프롬프트·동일 절대 위치의 참조/생성 문맥을 만든다. 원본 report/reference hash, 재발 횟수, 제외 이유를 보존한다. 토큰 재발만 검증하며 의미 오류/문맥 동등성/인과를 보증하지 않는다.
- `trace_token_flow`: 축별 최대512개 활성과 전체65,536개 scalar 한도로 MLP hidden256개를 한 번에 읽을 수 있다. 반복 모듈 호출도 같은 한도를 지킨다. 관측되지 않은 functional edge는 계속 미확인으로 표시한다.
- 선택적 `leave_largest_prompt_out_gain_positive` 검사와 그 실제 값 보고를 추가했다. 한 문장만의 개선을 분산된 개선으로 통과시키지 않는다.
- 기존 분석 스킬에 실제 생성 실패를 사용하도록 반영했다. 매번 별도 가중치 수정 Python을 만드는 대신 기존 MCP의 명시적 쓰기/누적 revision을 사용한다.

기능 검증: 전체94개 테스트 통과. 실제 재발/2회뿐인 재등장/EOS 뒤 가짜 반복/holdout/prompt 불일치와 wide MLP 흐름/총량 거부를 검사했다. 개선 분산 대조는 통과하고, 단일 문장 기여만 있는 대조는 거부했다.

## 사전 고정한 새 실험

기존004의128개 ID와 동일한 참조 토큰열을 제외했다. 공식 TinyStories 고정 revision의 story를 seed2026110405로 섞고, 점수와 무관하게 길이160~240토큰으로 추출했다. 분석32/개발64/독립128개다. pretrained 모델의 학습 중 비노출을 보증하는 데이터는 아니다.

원본 TinyStories-1M은 저장 파라미터3,745,984개, GPTNeo8개 block, width64, MLP256이다. 프롬프트24토큰, greedy CUDA 최대128토큰, EOS 중단/cache 사용을 고정했다. 원본 평균 반복률은 분석12.5866%, 개발9.2777%다. 길이 필터가 이전 실험과 달라 두 run의 평균을 동일 모집단으로 직접 비교하지 않는다.

개발과 최종 기준은 반복률2%p 이상 감소, paired bootstrap95% 하한>0, 가장 큰 개선 문장을 뺀 나머지 평균 감소>0, 정상 reference NLL 증가≤0.01, accuracy 감소≤0.01, 짧은 출력 비율/중앙 길이 보존이다. 기준은 첫 모델 실행 전에 고정했다. 개발도 적응적으로 여러 후보에 노출되므로 독립128개 최종 평가를 따로 둔다.

새 원본 생성에서 실제8-gram이3회 이상 재발한8개 문맥을 MCP로 구성했다. Claude Opus5.5가 이 관측과 실제 weight/계산을 바탕으로 값과 후속 수정을 선택한다. Codex host는 분석 도구·검증과 최종 독립 평가를 담당한다. 최대3개 primary+1개 control, worker forward요청65회다. 원본을 고정하고 parent 추론 결과를 본 뒤 `revise_candidate`로 두 후속 누적 수정을 시도한다. 근거가 없으면 성공을 강제하지 않는다.

실험 실행 및 최종 평가 결과는 종료 후 아래에 기록한다. 이전 loop/test는 재개하거나 재선택에 사용하지 않는다.

## 개발 편집과 실제 정상 손상

실제 수정 tensor는 `transformer.h.7.mlp.c_proj.weight` [64,256]이다. `a[t,j]`를 해당 모듈에 들어오는 실제 활성이라고 하면 출력은 `Σ W[:,j]a[t,j]+bias`다. 열157을0.75배 하면 같은 입력의 출력 변화는 `-0.25 W[:,157]a[t,157]`이다. 이 식은 정상 문맥에도 똑같이 적용된다. 활성 부호가 문맥마다 반대라면 같은 weight 수정도 반대 방향의 신호 변화를 만든다. 이후 최종 정규화·vocabulary 출력·greedy 후속 입력은 이 affine 식만으로 예측되지 않는다.

처음 layer5~7의 MLP hidden256개를 읽어 두 생성 문맥의8개 위치에서 높았던 layer7의113/157을 골랐다. 그러나 선택에 쓰지 않은 다른 생성 문맥에서는 두 활성 모두 음수인 반증도 있었다. 8개 인접 위치를8개의 독립 프롬프트로 해석하면 안 된다. 이번 실행은 이 약한 가설을 실제로 반증하는 실험이며 robust한 반복 전용 feature 발견을 주장하지 않는다.

| 후보 | 원본 대비 최종 수정 | 변경값 수 | 개발 반복 감소(%p) | 정상 NLL 증가 | 정상 참조 NLL 악화 문장 수/64 |
|---|---|---:|---:|---:|---:|
| 01 | 열113/157 각각0.5배 | 128 | 0.069 | 0.020525 | 61 |
| 02 (01의 child) | 열113복원,157만0.5배 | 64 | -0.481 | 0.008012 | 52 |
| 03 (02의 child) | 열157을0.75배로 재수정 | 64 | 1.448 | 0.002200 | 43 |
| 04 (원본 분기의 반대 대조) | 열157을1.25배 | 64 | 2.306 | 0.001543 | 41 |

문장 수는 참조 문장당 평균 token NLL의 악화 수다. 그 문장들이 전부 오답이 됐다는 뜻은 아니다. 원본과 동일한 0변경 patch의 MCP 추론으로 문장별 원본 값을 동결 후 추가 집계했고, 원본 baseline NLL/accuracy와 정확하게 일치했다. 이 추가 집계로 후보를 재선택하지 않았다.

실제 parent 연쇄는01→02→03이다. 02는64개 값을 원복하고 나머지64개를 유지했다. 03은남은64개를다시바꿨다. 예를 들어 `[0,157]`은 원본0.033855754882097244 → 02의0.016927877441048622 → 03의0.025391817092895508이다. 누적 patch의 재계산, source/parent hash와 실제 새로 로드된 모델 값 일치를 확인했다. 최종03의 patch SHA는`4c6d5224d44a0969715939ada4ee8cfcdcfc4bd68a4721831fa59056f1b977ba`다.

전체 모델 변경 개수는 작아도 수정 tensor의 상대L2는01에서4.14%,03에서1.50%다. 개수가 작다는 사실이나 일부 문맥의 작은 local delta는 정상 기능 보존을 보증하지 않는다. 01→03에서 손상 크기를 낮추는 수정은 작동했지만, 이것이 원본보다 좋은 모델이 됐다는 뜻은 아니다.

## 반대 대조와 판단

04는03과같은64개 좌표에 FP32 오차 내 같은 크기의 반대 변화다. source-relativeL2는03=0.0149843540,04=0.0149843536이다. 세 경쟁 가설의 예측과 대조 선택 규칙을 실행 전에 기록했다. 다른 크기를 sweep하거나 loss를 피팅하지 않았다.

줄이는03과늘리는04가 모두 개발 평균 반복을 줄였고, 정상NLL은둘다증가했다. 03의 감소95%구간은[-0.601,3.501]%p,04는[-0.799,6.513]%p로 둘다0을포함한다. 04의 평균 개선 약65.5%는 한 문장에 집중됐다. 이 결과는 단순한 ‘이 열이 반복을 쓰므로 감쇠하면 고쳐진다’는 설명을 지지하지 않는다. 모든 가능한 인과 역할을 배제한 것은 아니다.

사전 선택한 최고 개선/최악 악화/지표 동일 문장의 실제 생성도 비교했다. 04는 한 퇴행적 구문을 완화했지만 다른 정상 이야기에는 새로운 나무 오르기 문장 반복을 만들었다. 03은 기존 반복을 더 이르게 시작한 사례도 있었다. 지표가 좋아지는 것과 의미·문법·이야기 품질이 좋아지는 것은 별개다.

사전 규칙대로04가 모든 개발 기준을 통과하지 못하면03을 진단용으로 유지했다. 어느 후보도 개발 gate를 통과하지 못했다. 실행 검증은8개 모두 통과했고, Codex host는 실험 증거의 완결성만 승인했다(`verified=false`). 모델 개선 승인이 아니다. 최초 worker의 대조/문장검토 생략은 host가 미완료로 판정했고, 같은 loop의 두 번째이자 마지막 호출에서 보완했다. 실제 worker 모델은Claude Opus5.5 두 번이며 이전 loop는 열지 않았다.

추가 분석 보고서에는 같은 token sequence/위치를 중복 제거한 `context_evidence`를 구현했다. 별도 ID를 붙인 같은 문맥을 새 문맥으로 세지 않는다. 이 필드는 위 동결 실험 종료 후 추가한 것으로, 위 worker가 사용한 고정 package와 구분한다. 전체95개 테스트와 스킬 구조 검증을 통과했다. 문맥 수 표시 개선 자체가 모델 성능 향상을 입증한 것은 아니다.

## 최종 독립128개 결과 — 개선 미입증, 채택 안 함

후보03과 source/config/protocol/decoding/decision hash를 고정하고 loop를 `evaluation_freeze`로 종료한 뒤 봉인 데이터를 열었다. 원본·후보 각각16개 묶음의 생성32회와 최종 정상 reference 비교1회가 모두 성공했다. test를 보고 후보·수정값·기준을 바꾸지 않았다.

| 측정값 | 원본 | 후보03 |
|---|---:|---:|
| 평균 반복률 | 6.0597% | 6.5118% |
| 정상 참조 NLL | 2.28592174 | 2.28854339 |
| 정상 참조 token accuracy | 49.0076% | 48.9334% |
| 생성 길이 중앙값 | 128 | 128 |
| 16토큰 미만 생성 비율 | 0% | 0% |

반복 감소량은 **-0.4521%p**, paired95%구간은 **[-2.5611,1.6950]%p**다. 표본 평균은 악화했고 구간은0을포함하므로 반복 개선도 통계적으로 유의한 반복 악화도 확정할 수 없다. 문장별 반복 지표는38개개선/55개악화/35개동일이다. 동일 지표가 동일 텍스트를 뜻하지는 않는다.

정상 reference NLL은0.002622증가했다. 128개중91개문장의 NLL이악화했다. NLL 감소량의 paired95%구간도[-0.003440,-0.001776]로, 작은 정상 예측 손상이 재현됐다. 이 폭은 사전 허용회귀한도0.01이내지만 원본보다 좋아졌다는 뜻은 아니다. 반복 최소개선/CI/최대기여제거검사는 통과하지 못했고, 개발도 부적격이므로 **adoption_passed=false**다.

독립 raw token ID로 EOS 경계를 다시 적용해 반복률과2,000회 bootstrap 구간을 별도 재계산했고 저장 결과와1e-12이내로일치했다. source·config·후보patch·protocol·decision이 평가 전후 같았다. ## 원인에 대한 결론과 개선 범위

파라미터가 저장/적용되지 않는 오류는 확인되지 않았다. 실제값 변경·복원·재수정과 실제 forward 변화가 연결됐다. 확인된 문제는 잘못된 초기 실패 대리표본, 소수 선택 문맥에 의존한 신호 해석, 정상 문맥에도 쓰이는 writer 전체 열 수정, 작은 적응형 개발평가의 불확실성이다. 양방향 대조와 독립 음성 결과는 이번 단순 방향 가설의 일반화를 지지하지 않는다. 이것이 모든 층·모델·수정 방식의 불가능을 입증하는 결과는 아니다.

실제로 개선한 것은 실패 문맥 구성, MLP 전체 활성 관측, 문맥별 통계, 불확실성·집중도 평가와 반대 대조를 요구하는 스킬이다. 모델에서는 정상 손상을 줄이는 복원·재수정까지 성공했으나 원본보다 성능이 좋은 후보를 얻지 못했다. 실패 후보를 채택하지 않고 원본을 유지한다.

다음 의미 가설에는 선택에 쓰지 않은 여러 프롬프트와 같은 길이의 정상 생성 대조에서 부호·기여가 유지되는 근거가 필요하다. 입력 조건을 나타내는 신호와 residual에 쓰는 출력 방향을 분리해 분석하고, 정상 기능에 필요한 성분을 보존하는 국소 편집을 설계해야 한다. 현재 결과로 특정 layer/뉴런/계수를 권장하지 않는다. 새 가설은 새 독립 데이터와 별도 실험 계약으로 검증해야 하며, 이번 test의 피드백으로 현재 후보를 재조정하지 않았다.

스킬 변경의 근거와 한계는 [lessons.json](../experiments/failure-repair-005/lessons.json)에 기록했다. 현재까지 노출된 공식 문장352개는 [제외 목록](../experiments/failure-repair-005/exposed-example-ids.json)에 저장했다. 앞으로 같은 항목을 새 독립 test로 사용하지 않는다. 스킬 구조/코드의 검증 성공을 미관측 모델의 성능 향상으로 표현하지 않는다.

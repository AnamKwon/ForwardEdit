> **근거 상태.** 숫자는 호스트의 사전 등록 문서("9B 이미지 사실 편집")와 채점 파일, 편집기 노트에서 가져왔습니다. 실행 산출물은 이 저장소에 없습니다. 작업 공간, 편집기 기록, 생성 텍스트, 이미지, 가중치, 전체 가중치 지도가 해당됩니다. 이 기록은 11-28 0시 커밋 이후 11-29 0시까지 끝난 결과를 다룹니다.

## 오늘의 핵심
1. **Qwen3.5-9B의 가장 약한 공개 벤치마크인 SimpleVQA를 재현했습니다.**
   - 공개 수치는 51.2, 우리 재현은 **51.06%** 입니다(2025문항, thinking 켬, 공식 샘플링, Claude 채점기 1회).
   - 언어별로는 영어 47.58%, 중국어 54.55%입니다. 답을 피한 비율은 0.74%였고, 16384토큰에서 93문항이 잘려 오답으로 처리했습니다.
2. **"9B 이미지 사실 편집"은 동결되지 않았습니다.** SimpleVQA는 규칙대로 평가하지 않았습니다.
   - 편집기는 Claude opus입니다(effort max, 토큰·비용 상한 없음, 전체 가중치 지도 사용).
   - 순전파 25/50회, 후보 22개, 약 $50을 쓰고 스스로 종료했습니다. 확인 세트는 쓰지 않았습니다.
   - 가장 좋은 후보는 L31 어텐션 헤드 12의 출력을 2배로 키운 c01입니다.
     - 탐색 데이터: +1.07±0.59점
     - 검증 세트 500문항: 24.8 → 25.2 (+0.4±0.8)
     - 편집기가 보지 않은 문항 전체 676개: −0.3±0.66
   - 다른 시도는 모두 효과가 없거나 음수였습니다. 다른 헤드, 이미지 토큰 모달리티 이동, L30 선형 어텐션 축소, 후반 층 감쇠 조절을 시험했습니다.
   - 편집기 진단: 오류의 대부분은 지식이 없거나 대상을 알아보지 못한 경우입니다(숫자 44%, 지식 12%, 오인식 8%, 정답 표기 형식 25%). 여러 문항에 공통으로 고칠 수 있는 메커니즘은 없었습니다.
3. **편집 데이터는 대리 데이터로 만들었습니다(SimpleVQA는 편집기에 보여 주지 않음).**
   - 대리 데이터는 InfoSeek train과 ViQuAE를 대상(entity) 단위로 나눠 만들었습니다: 탐색 1200 / 검증 600 / 확인 600.
   - SimpleVQA 이미지와 지각 해시가 겹치는 이미지는 0개였습니다.
   - 호스트 진단(탐색 세트, Claude 채점)은 다음과 같았습니다. 이 결과는 편집기 프롬프트에 넣지 않았습니다.

     | 질문 형태 | 정답률 |
     |---|---|
     | 이미지 질문 | 39.2% |
     | 대상 이름을 글로 준 질문 | 65.3% |
     | 대상 이름 맞히기 | 33.8% |

     이름을 글로 주면 정답률이 크게 오르므로, "알아보기"가 병목의 큰 부분입니다.
4. **도구를 개선했습니다.**
   - 비전-언어 모델용 전체 가중치 지도를 추가했습니다(언어 모델 427개 텐서, 뉴런·헤드별 정답 토큰 기여도).
   - Qwen-VL의 이미지 패치 임베딩(conv3d)을 같은 값의 선형 계산으로 바꿨습니다. 이미지당 약 10초가 약 0.3초가 됐습니다.
   - 원본 생성 캐시 경로에도 같은 수정을 넣었고, 테스트는 280개 통과·1개 건너뜀입니다.
5. **지난 실험 기록을 메타 분석했습니다(호스트 기록, 산출물 미포함).**
   - 대상은 편집기 실행 159개와 원본 대비 후보 535개입니다.
     - 원본보다 나아진 후보는 45%였습니다.
     - 지도나 인과 추적 직후 첫 후보는 70%가 나아졌고, 인과 추적을 한 실행은 83%가 동결됐습니다.
   - 동결된 편집 95개의 성격도 살폈습니다.
     - 실제 향상 52개(편집 없는 기준을 넘은 것 27개), 손상 28개, 효과 없음 13개였습니다.
     - 같은 데이터로 학습한 비교군(LoRA·미세조정)이 15번 중 13번 이겼습니다.
   - 성공한 편집은 대부분 한 층에 국한된, 특정 연상을 바꾸는 좁은 편집이었습니다. 기술·형식 편집 23개는 CoT/thinking을 한 번도 넘지 못했습니다.

## 방향 결정
- 모델이 모르는 지식을 묻는 과제(SimpleVQA류)에는 추론 전용 LLM 편집을 더 투입하지 않습니다. 이번 실행과 메타 분석 모두, 이 방법이 통하는 곳은 "이미 있는 연상을 좁게 바꾸는" 경우였습니다.
- 다음 약점 선정 때는 "이름을 글로 주면 맞힌다"처럼, 모델 안에 지식이 이미 있다는 증거가 있는 과제를 우선합니다.
- 비전-언어 지도와 빠른 패치 임베딩은 이후 VLM 실험에 그대로 씁니다.

## 프로토콜 이탈 기록
- vLLM 생성 백엔드는 이미지 토큰 수가 작업자 프로세서와 달라서 GPU 점검을 통과하지 못했습니다. 그래서 편집기 순전파는 transformers 백엔드로 실행했습니다. 출시 전에 정했고 사전 등록 문서에 적었습니다.
- 도구 상한 때문에 실행 직전 설정을 바꿨습니다(순전파 50회, 한 번에 512문항). 검증·확인 세트의 이미지 문항은 600개에서 500개로 줄였습니다. 실행 전에 바꿨으며 데이터 해시를 갱신했습니다.
- 원본 생성 캐시 경로에 빠른 패치 임베딩이 빠져 있어서, 첫 원본 생성이 75분 걸렸습니다. 실행 중에 작업자를 수정했고, 수정 전 캐시는 다른 곳으로 옮겼습니다. 이후 쌍 비교는 모두 같은 경로로 계산했습니다. 결과 계산 규칙은 바꾸지 않았습니다.
- 편집 설계(thinking 끔)와 최종 평가(thinking 켬) 조건이 다릅니다. 동결된 편집이 없어서 이번에는 영향이 없습니다.

## 미대응 비판
- 이번 실험은 편집기 실행 1회이고, 비교군(LoRA)이 없습니다. 사용자가 편집과 원본의 비교를 요청했기 때문입니다. 따라서 "학습 기반 방법이라면 됐을까"에는 답하지 못합니다.
- 대리 데이터는 영어뿐이고, SimpleVQA는 절반이 중국어입니다.
- 채점기는 LLM 하나(Claude)이고, SimpleVQA 원본 점수도 한 번만 생성했습니다.
- 27B는 실행하지 않았습니다. 24GB GPU에서 nf4 가중치 19GB를 올리면 이미지 토큰과 긴 생각을 처리할 메모리가 남지 않습니다.
- 메타 분석은 관찰 자료이고, 과제와 편집 형태가 얽혀 있어 인과로 읽을 수 없습니다.

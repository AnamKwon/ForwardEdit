> **근거 상태.** 숫자는 호스트 평가 파일에서 가져왔습니다. 실행 산출물(작업 공간, 편집기 기록, sealed 문항)은 이 저장소에 포함되어 있지 않습니다.

## 오늘의 핵심
1. **지식 편집은 logit bias나 steering이 아닙니다.**
   - 4B CounterFact 편집은 S .903입니다. 같은 검증 세트에서 전역 logit bias는 최선 .536, 항상 켜진 steering은 .684, 정답 위치를 알려 준 steering은 .759였습니다.
   - 편집은 일반 문장 토큰의 0.0%에서만 켜집니다. 비교로, Barry가 재현한 루프 편집(LP 편집)은 토큰의 89%에서 켜졌습니다. (11-24 정정: 처음에는 WSP 루프 편집으로 잘못 적었습니다.)
2. **같은 조건 5회 반복에서 sealed 통과는 2/5입니다.** 다섯 번 모두 다른 층을 골랐고, 효과는 0~+17.5점으로 흔들렸습니다. 앞으로 결과는 통과율과 분포로 보고합니다.
3. **값을 정하는 능력은 학습·풀이 기반 방법이 강합니다.** 맥락 없는 sealed S는 LLM 편집 .682, ROME .806, MEMIT .897, LoRA .898이었습니다.
4. **생성 기반 평가(Mirage 방식):** NLL 비교로는 효과가 컸지만, 실제로 생성한 답이 새 정답인 비율은 낮았습니다. 맥락이 없을 때 LLM 편집은 3–4%, MEMIT은 26%였습니다.
5. **도구 개선 (모두 테스트 통과):**
   - 네 단계 데이터 분할: 학습 / 검증 / 테스트(동결 판정 전용) / 봉인
   - 확인용 문항 보호 장치
   - 같은 설계의 강도는 2개까지만 허용
   - 양자화 추론: 편집한 텐서는 bf16으로 유지
6. **큰 모델 준비:**
   - 9B: nf4로 8GB에 올라가고, 기준선을 계산했습니다(가장 강한 프롬프트 S .815).
   - 27B: 텍스트 전용 단일 파일로 변환했습니다.
   - MoVA-36B-A4B(MoE): nf4로도 GPU 한 장에 들어가지 않아 CPU 오프로드를 준비 중입니다.

## 방향 결정 (사용자와 합의)
- 편집의 강점은 계산 자원 절약에 더해 **"모델의 결함을 찾아 좁게 고치고, 기존 능력은 유지하는 것"**에 있다고 보고 이 방향으로 진행합니다.
- 실제 벤치마크를 네 단계로 나눠 씁니다.
- 실력 결함은 공식 조건(thinking 켬, 긴 출력)에서 남는 실패만 결함으로 봅니다. 효율은 토큰 예산별 정확도 곡선으로 따로 평가합니다.
- 편집기가 결과를 보고 강도를 고르는 탐색은 2개까지만 허용합니다(비판을 반영해 결정).
- 변경 비율 2% 상한은 v1 기준을 10배 완화한 임의 수치입니다. 실험 결과 실제로 걸린 적은 없었습니다.

## 프로토콜 이탈 기록
- 호스트 GPU 작업과 겹치면서 4B 블라인드 사실 편집 2 편집기 작업 1건이 실패했습니다. 이후 편집기 실행과 무거운 호스트 작업을 분리했습니다.
- Sparks 재현 첫 12건은 실행 폴더 이름이 정답을 노출해서 무효 처리했고, 무작위 폴더로 다시 실행했습니다.
- 상한 비교 실험의 첫 sealed 평가가 다른 작업과 겹쳐 메모리 부족으로 중단됐습니다. 결과를 내기 전에 중단됐으므로 그대로 다시 실행했습니다.
